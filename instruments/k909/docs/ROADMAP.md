# K909: roadmap

Each milestone ends with something you can run and check, and is committed and pushed when done. k303's golden renders and the rack tests must stay green throughout.

| # | Milestone | Done when |
| --- | --- | --- |
| D0 ✅ | **Skeleton** | `instruments/k909/` (`k909_dsp`, `k909_ui` QML module `K909`) and `apps/k909/`; registry entry; `pw-jack ./build/bin/k909` opens the empty panel, scaled, with the header and section labels, a JACK client `k909` with `out_L/R` and `midi_in`, silent. Result: parameter table (31), silent `Engine` with MIDI Learn CCs, `Drums` controller (Tempo and START/STOP drive the standalone transport), registry entry (channel 10, actions `patternA`–`patternH`, `startstop`), `tst_k909`; verified in the app: JACK outputs and both LX49 ports connect |
| D1 ✅ | **Voices** | All 11 voices in [DSP.md](DSP.md); `k909-render` writes a WAV of every voice in turn and a demo beat; `tst_voices`: each voice is non-silent, bounded, decays to silence, deterministic, little energy above 20 kHz; `--bench` within budget. Result: all voices, plus MIDI notes (velocity, accent at ≥ 100, sample-accurate) from D2 and the knobs from D0; `tst_voices` (also choke, retrigger without clicks, Volume); under 0.6% of the energy above 20 kHz; bench 1.05% of a core with all 11 voices on every beat |
| D2 ✅ | **Panel and notes** | Every knob on the panel and wired (`Drums` controller on `ParamController`, `panel.json`) (done in D0); MIDI notes play the voices with velocity and accent (done in D1); right-click on a track name auditions it; knob style closer to the reference (black, orange pointer); screenshot matches the layout in [UI.md](UI.md). Result: audition goes through a new lock-free command queue (`Engine::post`, which D3-D4 extend with pattern edits); `Knob` gained cap and pointer colors (k303 unchanged) |
| D3 ✅ | **Sequencer** | Tracks × steps playback on `StepClock` with accent, Total Accent, Shuffle, hat choke, play order and scale; step LEDs; START/STOP and Space; a golden render of a fixed pattern; `tst_sequencer` (step timing to the sample, shuffle offsets, choke, pattern change at the end of the pass). Result: all of that except pattern change (moves to D4 with A–H). Pulled forward from D4: track select (click a name, ↑ ↓), step toggling off → on → accent, CLEAR (Shift: whole pattern). Four factory patterns; pattern 0 loads at startup. `k909-render --pattern N` renders through the sequencer and transport (reference renders saved for byte comparison). Shuffle uses `StepClock`'s gate point and its new `stepCount()`. Play order has no panel control yet (Forward) |
| D4 ✅ | **Patterns and storage** | A–H (change at the end of the pass while playing), length, scale, play order; `patterns.json` with the factory patterns seeded on first run (`tst_pattern`). Result: as planned; the waiting pattern is editable (edits name their slot), Clear replaces the pattern in one queue item, keys A–H. Tests in `tst_k909` (file format, clamping, save and restore through the controller) and `k909_tst_sequencer` (pass boundary, order restart, cancel, edits to the waiting pattern). `StepClock::restartPass()` added to the shared clock |
| D5 ✅ | **MIDI Learn and the rack** | Learn for all knobs, A–H and `startstop`; K909 in the Krate rack on channel 10 (Tempo and START/STOP hidden there); `krate-render` includes it; rack tests extended; on the LX49, pads play K909 on channel 10 while the keys play the focused instrument. Result: UNMAP / AUDIO / LEARN, status line and meter on the panel (L, Esc); START learnable as `startstop`; K909 between k303 and Klick in the rack (saved mappings are keyed by id, so existing sessions keep working); `krate-render --k909 LEVEL [--k909-pattern N]` (without it the render is byte-identical to before); `k909_tst_rack` (channel 10 reaches K909 whatever has focus). K909 includes are now `k909/dsp/...`, `k909/app/...`, since k303 has files of the same names. LX49 pads: to be confirmed on the hardware |
| D6 ✅ | **Polish** | Voices tuned by ear (DSP.md updated with final values); qmllint clean; accessibility names; README section. Result: −3 dB output trim for headroom (demo beat peaks at −3.5 dBFS before the soft clip); accessible names everywhere (`ParamController::label()`, `LcdField.name`, full-word parameter labels); step buttons keyboard-reachable; DSP.md and README updated; qmllint clean. Ear tuning continues from listening feedback (see Later) |

## Later

| Feature | Notes |
| --- | --- |
| Sound tuning by ear | Per-voice adjustments from listening (kick body and click, snare snap, hat brightness, clap spread); DSP.md follows |
| Kits | Saved knob sets with a KIT display and WRITE, as in the reference layout |
| Flam | Per-step flam, a fourth step state |
| Parameter locks | Per-step tune/decay values |
| Per-voice outputs | `outputChannels()` > 2; the rack gives each a port pair |
| Pattern chaining / song mode | Shared with k303 if it happens |
| Step record | Play the pads while running to write steps |
